# PathFinder — Navisworks Manage 2027

Two-tab cable routing proof of concept, version 1.1.11, for the Navisworks Manage 2027 .NET API (24.x), .NET Framework 4.8, x64. Selected routes form a 3D graph in metres; its edge lengths and endpoint attachments determine the cable length between From and To.

## Use

Open a 3D model, then choose **Path Finder → Tool Panel**.

1. On **Routes**, select tray containers or individual tray leaves in the Navisworks Selection Tree. Choose **MV**, **LV**, and/or **Control**, then click **Add / update selection**. Every deepest descendant with geometry is included; selecting a leaf itself also works. The grid shows each selected root, its geometry-leaf count, and editable permissions. A later rule overrides an earlier rule for overlapping leaves. **Remove rule** removes selected grid rows.
2. On **Path**, enter exact **From** and **To** display names, preserving any initial `=`. Lookup uses only currently visible objects with visible geometry; hidden objects and descendants of hidden parents are skipped. Alternatively select exactly one visible model object and press its **Use selection** button. This resolves multiple visible objects with the same display name and unnamed imported geometry. Choose the cable type and press **Calculate path**.
3. Set **SECONDARY distance (m)** beside Connection gap (default **2.00 m**, adjustable from **0.00 to 1000.00 m**). The result lists route codes in traversal order and estimated length. `/SECONDARY` is inserted at the From and/or To end when its selected equipment approach is strictly longer than this threshold. A distance exactly equal to the threshold does not trigger it. Changing the threshold clears the previous result and stays in manual mode; use Calculate path to refresh it in manual mode.
4. **Show path** selects exactly the used route leaves in the native Selection Tree. From is green, To orange, and route geometry blue, all at 0% transparency. Native selection highlighting follows the user's Navisworks preferences and may overlay these colours. Every other model object receives 95% transparency. A yellow world-anchored 3D line displays the calculated cable path, including endpoint attachments; it remains visible over the solids. If From and To overlap, shared geometry is purple. **Restore view** removes the line and restores the previous visible temporary materials and previous selected items. A later manual selection or Clear is preserved. Permanent materials and hidden states are preserved.
5. **Reverse** swaps From/To and reverses the result, including SECONDARY markers. A displayed path updates its endpoint colours and line direction.

**Prefer vertical equipment approach** starts checked. First find the nearest allowed centreline in 3D. Among approaches whose complete 3D length is no more than that nearest distance plus **Connection gap**, prefer the smallest horizontal XY offset, then the shortest approach. This bounded search keeps a remote storey from winning just because it lies directly below an object. Vertical tray pieces use the nearest height. Uncheck the option to use the nearest 3D projection alone. Both modes use the same bottom-face base point, category/visibility filtering and actual approach length; changing the option clears the old result and stays in manual mode. The routing API preserves nearest-3D behavior unless `RoutingOptions.PreferVerticalApproach` is enabled.

Name lookup runs a native Navisworks search for each requested name and caches its matches, then checks their current visibility on every lookup. Leading/trailing whitespace and letter case are ignored. It does not build a managed index of every name in the model.

Route labels use the nearest named logical ancestor above Tube, Bend, Branch, Elbow and other fitting components, within the assigned route root. Digit-leading IDs such as `/5LD04` and qualified component names such as `/5LD04/B1` are supported. For example, children beneath `/5LD04` display `/5LD04` rather than `/B1`. Independently named logical pieces retain their complete codes, including `/C107-7`. Naming is separate from shape fitting and does not change calculated geometry or cable lengths.

**Design length** appears as the final output line, rounded upward to a whole metre. The extra fields are:
- **Spare for connection (m)**: 6.00 m by default, added once per cable.
- **SECONDARY Length (m)**: 0.00 m by default. At each endpoint marked `/SECONDARY`, this replaces that endpoint's measured approach length. Unmarked approaches retain their measured length. Zero replaces a marked approach with zero metres.
- **Length increase (%)**: 0.00% by default, applied to the corrected cable length plus connection spare before the final ceiling.

For example, a 94.249 m cable with one 2.710 m SECONDARY approach, an entered SECONDARY Length of 5 m, 6 m spare and 10% increase gives `(94.249 - 2.710 + 5 + 6) * 1.10 = 112.7929 m`, so **Design length: 113 m**. These fields update an existing result immediately while keeping its route and displayed geometry. They do not start another route search. Reverse preserves the design length.

**Calculation is permanently manual.** There is no Pause checkbox or automatic calculation timer. Changing endpoints, cable type, tolerances, approach preference or route selection clears the old result; press **Calculate path** to calculate again. Model capture is batched on the Navisworks UI thread; graph calculation uses detached values on a worker. **Cancel** stops capture/calculation. There is no automatic `UpdateFiles()` call.

Route rules belong to the current pane/model session. Opening/replacing/appending a model, changing model transforms or document units, or updating the model clears stale rules/results. Re-add the route selection afterward.

Hidden tray leaves are excluded from the calculated network. **Hide/Unhide** clears any calculated/displayed path while preserving route rules and picked endpoint identities. Recalculate to use the current visible objects. Unhidden trays participate again without re-adding their rules; a hidden picked endpoint must be replaced or unhidden. The grid's leaf count describes the complete assigned hierarchy, including leaves currently hidden. Visibility means Navisworks Hidden state, including ancestors; transparency and camera occlusion do not hide an object for routing.

## Geometry and engineering limits

Named **FTUBE / TUBE / STRAIGHT** leaves use measured mesh end sections to reconstruct their centreline, including rotated and short components. A short part whose width exceeds its length needs unique compatible neighbouring port evidence. Physical cap planes may lie inside the overall bounding box when supports or bolts protrude past them. Named **BEND / ELBOW** components use measured port planes, a validated circular surface and compatible neighbouring arms to reconstruct their actual plane, angle and tangent stubs. Curve pieces span at most five degrees. An older axis-aligned quarter-circle reconstruction remains available when only world-face evidence is present.

Native mesh reads cover assigned visible route leaves, with primitive/fragment and byte limits. Detached triangles and face evidence are cached with their bounds and active transform. Geometry fitting and surface indexes run on a worker and are reused only after a fresh live capture proves that visibility, categories, names, bounds and transforms still match. Unsupported, missing or ambiguous centreline evidence retains the bounding-box approximation and is reported for review. Its valid full-leaf mesh can still measure physical clearance, including any hardware in that leaf. Reconstructing a bend preserves physical port positions and any remaining gap between components.

An AABB tree finds candidate pieces. Measured surfaces use exact triangle distances in a bounded surface index; their contact witnesses project onto the corresponding centreline. Validated straights use mesh clipped to their actual body section, while bends use their two physical end sections. The sparse graph contains original polyline vertices, endpoint projections and contacts, without regular sample points. Bends connect to other trays only through their physical ports; equipment endpoints may still project to the curve's interior. When validated surface evidence is unavailable, analytical centreline contacts are used and reported. Equal minimum-clearance witnesses from both search directions are retained, and parallel contacts also consider equipment attachment stations. This lets cable length decide between equal-clearance contacts without depending on which query warmed the cache. Node limits count actual graph vertices rather than samples per metre.

Immutable surface indexes cache at most 128 peer queries and 256 local-section proofs per surface. Exact successful proofs are reusable at other gap thresholds; a failed search is reused only within its proven cutoff. Cancellation is checked on cache hits too. Changing the live geometry creates new surface identities, so old proofs cannot authorize new contacts.

**Connection gap (m)** measures the empty space between validated tray surfaces: 0.25 m by default, adjustable from 0.01 to 1.30 m. Missing validated surface evidence uses a centreline-distance fallback, shown as **Connection gap review**. The cable length always includes the complete centreline connector, even when the empty space is shorter because trays have a finite width. A larger gap may connect nearby parallel trays; proximity does not prove an installed connector. Disconnected selected approaches produce a no-path result with their codes, attachment distances and chosen tolerance. Forbidden cable categories are excluded before both endpoint attachment and graph construction.

Path selection first minimises the **number of connection gaps between trays**, then their **summed clearance**, then the **total cable length**. Each gap is ranked in additive integer micrometres, so sub-micrometre mesh noise cannot defeat a shorter cable and the ordering stays transitive. Displayed gap and cable lengths retain the unrounded physical values. Continuous travel within a tray and touching surfaces do not count as gaps. General contact precision is 0.000001 m. Only two measured, opposing and compatible physical port sections can additionally treat a residual up to 0.0005 m as native mesh precision. This avoids skipping real short components because of micrometre seams; their actual lengths remain included in the cable length. From/To attachments, including SECONDARY, do not count as inter-tray gaps. Reverse preserves both gap metrics.

Lengths remain approximate. Non-planar curves, tees, complex fittings and ambiguous mesh profiles need a geometry review; inferred circular curves approximate the mesh rather than extract authored CAD curves. Surface clearance is measured between retained triangles and is not a solid-volume containment test. Each From/To base point is the centre of the bottom face of its visible world-space bounding box: X and Y are the box midpoints, Z is the box minimum. Hidden descendants are excluded before taking these bounds, and all three coordinates are converted to metres. This same point is used for route attachment, SECONDARY distance, cable length, the displayed cable line and freshness checks before Show path. `/SECONDARY` is a textual attachment marker and does not create model geometry. Cached paths are checked against both current bounds and active transforms before Show, including rotations that leave the bounding box unchanged.

Show path captures and restores the whole model's appearance synchronously on the native UI thread. Full-project visualization performance remains unverified; worker calculation timings do not include loading, native capture or Show/Restore. Start with selected tray subsets. Graph size and candidate limits fail clearly for excessive or dense networks; dense physical contacts can still require quadratic work. Calculation always stays manual.

Names preserve full codes such as `/BC001`, `/DFBC009`, `/VFD007-2`. Rules are explicit; names do not grant cable permissions automatically. The supplied tray catalog supports A→MV, B/DFB→LV, BC/DFBC→LV+Control, C/DFC→Control. VFD and grounding require an explicit user decision within this three-category PoC.

## Build and test

Run `scripts/Build.ps1` in PowerShell. It discovers Manage 2027 and Visual Studio MSBuild; override with `-NavisworksInstallDir` and `-MSBuildPath` if needed. Build output is `AddinRibbon/bin/Release`. The installed SDK assemblies `Autodesk.Navisworks.Api.dll`, `Autodesk.Navisworks.ComApi.dll` and `Autodesk.Navisworks.Interop.ComApi.dll` are required; each is referenced with `Private=False` and is never copied into the plugin. Build does not deploy automatically.

Run `dotnet run --project tests/PathFinder.Routing.Tests -- <optional-local-excel-fixture.json>` for the package-free routing and geometry harness. Version 1.1.10 passes 93 checks including all 327 local Excel tray-code fixtures; without the optional fixture there are 92 checks. The linked production routing code is tested directly, including hierarchy naming, measured straights and circular bends, hollow triangle surfaces, physical gap ordering, numerical precision, local tied contacts, cold/reverse cache invariance, bounded caches, parallel interior attachments, vertical approaches and conservative fallback. A synthetic hierarchy fixture produces `/SECONDARY/5LD04/SECONDARY` at 23.054 m and Design length 39 m, with identical path points, attachments and gaps before and after relabelling. This fixture does not validate the new project's native model. Private fixture data is excluded from the public repository/package.

After installing the matching Release DLL and closing Navisworks, run `scripts/Test-Navisworks.ps1` inside a fresh hidden Manage 2027 instance; it writes local results, pane previews and scene/overlay images without saving the model. **All 47 native groups passed for the exact installed 1.1.11 DLL**, including route selection, Restore/Dispose ownership, manual selection/Clear, repeated Show/Reverse, unchanged manual calculation state, bounded hierarchy names, visibility, endpoint base points, appearance restoration and the rendered cable line. Release and installed DLLs match by SHA-256. Current and historical verification is recorded separately in [validation notes](docs/Validation.md).

The frozen 1.1.10 read-only run on the second project passed **26 native checks** using a unique assembly identity built from that Release source. Its actual route is `/SECONDARY/5LD15/5LD04/SECONDARY`: the first two traversed geometry leaves belong to `/5LD15`, and the remaining eleven belong to `/5LD04`. The legacy parser collapsed both into `/B1`. Relabelling preserves exactly the path points, segment IDs, attachments, gap metrics, 23.054 m displayed length and 39 m design length. The loaded engine identity, file path and checksum were verified in that host; private model data remains local. Version 1.1.11 does not change this routing or geometry code.

A frozen native mesh snapshot of 869 assigned leaves supports a separate detached replay: 571 straight components and 84 bends are fitted; 114 straights and 78 bends retain the reported centreline approximation. Measured surface evidence covers 861 leaves, with 937 indexes; missing surface evidence remains visible in the gap-review diagnostics. The final-source replay confirms identical path points after cold, forward-prewarmed and reverse-prewarmed queries. On this machine its warm worker calculations take about 8–15 ms for the selected cable category and 20–29 ms with all 869 leaves eligible. These are detached worker measurements, excluding model loading, native mesh capture and visualization. **All 44 final targeted read-only checks passed in Manage 2027 for the unchanged 1.1.7 routing engine; the model remained unmodified and the isolated host closed.** The Excel catalog validates names and category mapping, not spatial routing or exact engineering lengths.

The active UI is `AddinRibbon/Ctr/PathFinderControl.cs`, created by `ClDockPanelUpdate`. Legacy `Algo.Designer.cs` and other old controls remain as reference source and are excluded from the current project. The dock explicitly allows resizing, starts at a useful size and reapplies Dock=Fill after native-parent attachment; font scaling has an explicit baseline.

Run `scripts/Package.ps1 -Destination <new-empty-directory>` to create the DLL/XAML/icon package and checksums. Close Manage 2027, then run the package's `scripts/Install.ps1 -PackageDirectory <package-directory>`. The installer writes `Plugins/AddinRibbon` beneath Manage 2027 and backs up any previous folder under `PathFinderBackups`. Restart Navisworks to load the DLL. Do not install it in Freedom or use a different year's Autodesk API libraries.

See [action plan](docs/ActionPlan.md) and [validation notes](docs/Validation.md) for implementation scope and test evidence.

In Manage 2027, temporary material overrides mark the document as modified. Restore view restores its previous appearance, while the native modified flag remains set. The add-on does not save the model or clear that flag.
